# 输入、上下文与多轮行为

## 1. 上下文的权威来源

一期连接内多轮上下文由 VoiceChat 保持。应用通过 input_item_id 区分用户输入，通过 response_id 区分模型输出，通过 call_id 区分一次调用；一份 WAV 可以包含多段 input，一个 input 也可以产生多个调用。三个标识不能互换。

最终 ASR 保存为用户转写并用于绑定业务输入，不代表模型收到的音频一定完整。原生查询采用模型 query，不根据 ASR 自动触发工具或替换 query。一般回答只能作为未验证背景，不能充当企业事实证据。

## 2. 持久化与执行快照

Store 保存 Utterance、业务 Turn、引用、交付记录和脱敏阶段信息。Coordinator 维护 epoch/revision/任务及租约，只有当前有效任务可提交。服务端 KB 和权限范围不接受模型或浏览器覆盖；历史读取、来源显示与后续上下文仍复核权限。

`task_context.py` 保留确定性来源条件和授权历史处理；它不是自然语言分类器。历史引用不会直接变成本轮新检索证据。原生 `NativeInputSearch` 的预算/累计来源仅属于当前连接的当前 input，ACK、调用 ID 和回答均不重置预算。

## 3. 连续输入与重连

音频持续发送，模型原生让话/语音开始事件驱动播放清理。普通发声或 Stop playback 不等于业务取消；明确取消或关闭才改变业务生命周期。新输入应建立新预算，但是否正确理解代词与上下文必须现场验收。

重连使用有界且重新授权的业务摘要，不恢复模型隐状态。文件中停顿被识别为两个 input 并不自动证明错误；需要分别观察第二段调用及回答。验证器等待完整 WAV 发送后最新 input 对应的非 ACK 回答完成，不能沿用第一段完成标记。

多轮和输入验证统一在 [验证操作手册](validation.md)，本页只描述已实现行为和限制。
