# 语音答案与交付边界

当前一期使用 `voice/relay.py` 的持续收发路径。本文描述实现语义，不声明所有真实交互已验收。供应商批次协议见 [工具契约](interfaces/voice-tools.md)，浏览器事件见 [门户协议](portal-protocol.md)。

## 1. 答案约束与实际口述

一般回答、固定 ACK 和知识回答分开记录。ACK 不是答案完成，一般回答没有公司来源；知识回答基于同一输入的累计有效证据。原生路径不安装一次性“发声许可”，工具等待也不停止音频时钟。

回答须关联当前 input/response/Turn。完整非 ACK 转写、非零音频及结束事件用于自动完成判断；Coordinator 检查实际口述文本与交付证据后唯一提交答案/引用。检查保留数字、条件等规则，但不是完整语义推理；`answer_complete=passed` 不保证事实准确或用户已听到。内容验收必须核对来源和听音。

`VOICE_MISSING_CONDITION` 等内容原因不能仅因音频正常结束就忽略。检查只应使用实际交付的证据及限定，不能用已剔除的截断 context 要求回答补充条件。失败状态与正文、来源分别保留，不将失败答案包装为 grounded 成功。

## 2. 结束确认、台账与恢复

DeliveryAttempt 区分 write_started、sent、unknown 等观察；网络写入与数据库无共同事务，不能自动重发未知状态的结果。原生批次每成员结清，实际函数通道只注入一份结果。

音频结束表示服务端发送完成；浏览器 Worklet 排空后 finished ACK 仅表示播放估计，不证明扬声器发声或用户听到。Stop playback 清下行缓冲，不取消查询；End call、明确取消、失效 epoch/revision 或权限变更按业务规则结清/关闭。旧响应不能提交到新任务。

连接内上下文由同一 VoiceChat 会话保持。轮换受配置的连接时限、空闲及待答条件约束；它是资源边界，不是工具循环的正常收口。重连只携带经授权的有界业务摘要，不恢复模型隐藏状态、录音或旧播放队列。

## 3. 等待进度与自然修订

API 能持续收发，不等于模型在工具等待期间会理解新的语音并完成修订。当前 NVIDIA Adapter 的增强等待能力未声明通过，不能用 env 开关、固定 ACK 或可见字幕冒充。门户 Check progress 读取真实任务状态，不虚构百分比；明确取消后可重新提问。

原生 speech_started 清除已经排队的播放，本身不撤销有效查询。停顿引起的分段、后续插话归属和跨轮指代需真实测试。本次只处理明确工具批次的结清，不修改 VAD 或把整份 WAV 强制当成一个 input。

本轮按 [统一验证手册](validation.md) 核对 Golden Yolk 第二段；长期标准见 [统一验证手册](validation.md)。兼容路径中的批准文本/续答许可、增强 Provider 模拟实现仍有测试，本页不将它们描述为一期原生路径。
