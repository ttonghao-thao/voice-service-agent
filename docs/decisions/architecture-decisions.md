# 当前架构决策

只保留本期采用的取舍。旧批准文本/许可补偿、替代 ASR/TTS 和多模型方案不属于本期，历史由 Git 追溯。

## 独立服务与唯一提交

VoiceChat 负责语音和原生工具选择，CueKB 负责知识检索。本项目保留 Gateway → Coordinator → Runtime → Registry，Coordinator 唯一提交业务答案。理由是复用现有权限、版本和审计边界，不新建调度服务。跨服务没有共同事务，未知交付不重发。

## 一条持续语音链路

一个通话保持一个 VoiceChat 连接，音频/ACK/答案持续转发。响应 ID 区分输出，不充当一次性发声许可。VoiceChat 自主选工具，不加分类模型或转写驱动补查；代价是工具漏调用仍须真实观测，Prompt 不能保证行为。

## 有限检索与累计来源

同 input 默认两次实际查询，原生 HTTP 不重试，相同参数复用并结束检索。保留累计来源及权限，允许诚实部分回答；不能靠无限检索补足知识缺口。终态引导不能强制模型，真正终态后新批次失败必须如实记录，不能计作成功回答。

## 明确批次，一次注入

VoiceChat 一次 function 输出可含多个调用，而后端使用一份待注入结果。audio_server 显式声明批次，API 在预算内串行处理并结清所有成员，回填一份累计结果。此改动局限传输层；不按时间猜测或按工具名合并，不改模型格式化逻辑。代价是 API/audio_server 必须配套部署。

## 播后检查与能力边界

原生模型直接生成音频，应用有限检查发生在文本/音频完成后；不能宣称播前真实性保证。音频结束、浏览器排空、实际听到和事实准确分别验收。连接内多轮保留模型上下文，重连只恢复业务摘要。等待工具期间的修订能力没有真实证据时保持未启用。
