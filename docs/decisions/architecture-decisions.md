# 关键架构决策

本页保存原因、代价和重新评审条件。2026-10-15 按 `63e7059` 修正 ADR-07 并增加生命周期决策；配置/字段不在此重复定义。当前模块关系见 [架构](../architecture.md)，工作状态归 [任务板](../TASK_BOARD.md)。

## ADR-01 独立服务与控制边界

**采用。** VoiceChat 负责实时语音理解、原生工具选择和语音生成，CueKB 负责检索；本项目经 API 控制会话/授权/任务/交付。保留 Gateway → Coordinator → Runtime → Registry，Coordinator 唯一提交。供应商事件隔离在 voice，SDK 隔离在 agent_runtime。

原因：应用不拥有 GPU 隐藏状态和 CueKB 索引，不能假设本地取消等于远端停止；独立升级需要可核对契约。代价：跨服务没有共同事务，必须用版本/权限检查、交付台账和明确 unknown。新增服务/子 Agent 前须证明其收益并重审提交权、预算和失败语义。

## ADR-02 原生选工具与两层工具

**采用。** VoiceChat 完整栈用 tools/instructions 从后台全局目录选择工具；应用按可信实现分派，不加分类 LLM、独立 Nano 文本服务。lookup/reasoned 是初始配置，dual_tools 不限制数量。外置 SDK 的工具选择参数用于知识执行，后台 search_knowledge 是独立工具层。

原因：重复分类增加一次串行调用且未证明改善原生选路；直查完整证据时零外置调用，复杂问题仍需外置推理。代价：原生漏/误调用率必须实测；general_qa 的工具网关抓不到所有漏调用。严格会话采用 knowledge_required，不能靠 Prompt 宣称零漏答。旧的“前台 WS 必须传 tool_choice=auto”解释已被当前协议方案替代；legacy 兼容模式仍保留。

## ADR-03 D2 与实际口述的证据等级

**采用 D2；D1/D3 计划中。** 当前可在工具返回证据后流式生成音频，有限检查发生在音频之后；外置批准文本与 Provider 实际转写也分别检查。转写通过、网络完成、播放排空和听到不得合并。

原因：现有 Provider 没有已验证的“先生成不可听草稿、批准后才播”的接口。代价：错误可能在检查前已播出，只能清剩余缓冲并明确失败；需要播前语义保证的部署不能把 D2 当 D3。未来 D3 必须有真实草稿/呈现关联和未批准音频零放行证据。候选细节保留在 [原 Q07 §6.3](../archive/2026-10-07/qa-routing-design.md#63-简单答案的三种合成等级)。

## ADR-04 控制、并发与恢复

**采用。** 发声/附和不自动取消业务；Stop playback、取消、替换、结束分开。epoch/revision/Turn/租约隔离旧结果；只有可关联的响应获得输出许可。旧 pending call 结清或关旧连接，写入不明记 unknown、不重发。

原因：清播放不应丢失用户仍需要的查询；重复发送可能造成重复口述，DB 与 WS 无法原子提交。重连恢复有来源的授权摘要而非录音/隐藏状态。代价：用户可能需要重新提问，浏览器 finished 仅是排空估计。改变恢复策略须同时验证网络断点、持久化、供应商调用及多响应播放。

## ADR-05 Provider 能力必须独立验证

**采用。** 等待期进度/自然修订需四项可信 Adapter 能力：等待交互、修订、明确 call 关联、旧调用结清。当前 NVIDIA 全 false，无环境变量/浏览器开关绕过；门户进度不依赖这些能力。

原因：持续收音、ASR 和固定 ACK 不证明新输入参与等待中的推理。增强模拟只验证应用控制流程，其 parent_call_id 扩展不能当真实协议。启用前按固定模型/模板/推理版本实测；[历史研究](../archive/2026-09-28/voicechat-research-review.md) 只作当时证据，不推断后续供应商版本。用户提及的 gpt-live-1 没有可确认的专属实现资料，本项目不声称复制其内部 Agent。

## ADR-06 范围、事实与部署

**采用。** 每次通话签发短期 capability，KB 范围由服务端与受限 Key 决定；历史/SSE/模型上下文都复核撤权。知识内容只作数据，不以 rank/引用存在替代事实验证。正式登录、多租户、交易等需独立需求设计。

一套正常部署 env/Compose、API/Web 两镜像，Web 内 Nginx 终止 HTTPS；显式模拟夹具是测试工具，不是第二套生产模式。原因：避免部署与验收行为分叉、密钥流入浏览器；代价是正常部署即使直查零外置调用，也仍要求配置已声明的真实外部依赖。旧固定共享客户身份、所有模式强制单 bridge 等历史表述不覆盖当前能力。

## ADR-07 social_only 与无工具响应的播前授权

**原首阶段默认方案已替代；社交直答推迟评审，未实现。** 当前企业验证采用已有 knowledge_required。输入是问候不代表开放式回答只有问候，错误 ASR 也可能丢掉业务请求；输入白名单和缓冲无法证明输出内容安全。

若再实施 social_only，必须先限定服务端批准话术或具备真实播前输出约束，并对重复旧答案复核权限。有界响应隔离只解决等待/关联问题，不创造工具调用。代价是当前严格模式牺牲一部分自然社交可用性；收益是先验证最小知识闭环，避免把新分类器当故障修复。完整依赖及替代架构的进入条件见 [方案](../q1003-target-architecture.md)。旧提议可从 Git 63e7059 追溯。

## ADR-08 响应完成与能力退出

**设计中；仅 PAD 保护已交付且待真实验证。** 自然 EOS、预算 EOS、协议结束、浏览器排空及业务完成分别记录；阶段期限有硬上限，静音包不能无限续期。已有 PAD 静音预算不自动证明语音完整，预算结束不能自动成为正常成功。完成原因贯通和预算调整须由现场证据指导。

若原生工具可靠性或开放式续答无法满足目标，另行评审启动级 ASR→业务→受控 TTS，保留 Coordinator/Registry/权限/台账。它改变 ADR-02 的原生入口，尚未获准实施；不在运行中自动回退，也不假定当前 VoiceChat 支持受控文本播报。

## 修改决策时

先定位受影响 ADR 与代码，再读对应主题/契约和必要历史依据。采用新方案时记录状态、原因、代价、替代对象与代码基线；旧决策标“已替代”并保留追溯入口。计划中的字段、控制能力和配置不能写入当前接口说明；实现状态变化时更新任务板，不要求全仓重写。
