# 当前关键取舍

类型：确认的架构理由，不复制实现/状态。实际行为见 [架构](../architecture.md)，需求见 [交付](../delivery.md)，后续设计见 [方案](../implementation-plan.md)。

| 取舍 | 理由与代价 |
| --- | --- |
| 天气、通用知识、专业知识库并存 | 固定产品能力；依赖缺失或旧 Provider 限制不能解释成仅知识库产品 |
| 通用知识受控兜底 | 保持可公开发送的独立查询和来源边界；不能把内部失败/未知意图自动送公网 |
| 独立语音/知识服务，Coordinator 唯一提交 | 保留部署、权限和审计边界；跨服务没有共同事务 |
| 原生委派 + 确定性 Router，无第二个路由模型 | 原生触发与解析分别验收；不能保证所有模型输入都触发或保持型号正确 |
| Sophon ASR 仅展示，task 提供查询语义 | 语音理解归模型，音频活动判断归属；不能用转写补调/修正 task；NVIDIA 最终 ASR 契约仅限其兼容路径 |
| 每输入一次问题级 query、成功包再 validate | 内部补召回由 CueKB 有界完成，终态后调用只结清，不重查 |
| 完整组 + Provider 对应预算 | 不截断条件、不猜 tokenizer；NVIDIA 精确最终 NeMo 包，Sophon 独立 Commentary 边界 |
| 输入/播放/业务分离，回答认证分层 | 普通发声停止播放不取消查询；ASR/发送/回执/排空不证明理解、完整覆盖或事实正确 |
| API/Web 配套镜像，数据库独立迁移 | 推送不等于部署；持久卷、权限和角色数据不能随容器替换删除 |
| 外部 VoiceChat 配套快照 | model/data/audio_server/模板及 API 必须匹配；不热换单文件后宣称通过 |

NVIDIA 的重复检索、终态立即循环断连、model query 替代其最终 ASR、related-input 自动视作回答等已替代方案不得重引入。该 Provider 的逐 token 消费、复验到写入窗口和固定连接寿命仍是实现约束，不能当作长期已验收设计。
