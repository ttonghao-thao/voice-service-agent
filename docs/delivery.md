# 一期交付说明

更新：2026-10-22，开发主线 `main`，基线来自 `codex/q1003`。本文明确交付范围；实际架构见 [architecture.md](architecture.md)，待办与证据分别见 [任务板](TASK_BOARD.md) 和 [统一验证手册](validation.md)。代码完成、现场验证和产品放行是三个不同状态。

## 1. 需求与目的

建设仅支持英文（en-US）的全双工知识客服。用户通过 Web 麦克风或固定 WAV 发起语音问答，私有部署 NVIDIA VoiceChat 负责理解、原生工具选择、语音回答及连接内多轮上下文；外部 CueKB 提供企业知识。本项目负责门户、会话、授权、工具执行和有来源答案交付。

本期先打通一个完整、有据的知识问答，再验证连续多轮。查询得到部分信息时回答有据部分，明确本次材料无法确认哪些细节；不得把未检索到说成事实不存在。一般问候和通用知识允许直接回答，不能伪装为企业知识答案。

设计保持简单：一个 VoiceChat 会话、一条持续音频链路、一个原生 `search_knowledge_base(query)`、每输入默认两次实际查询。没有额外分类模型、独立 ASR/TTS、外置答案模型或转写触发的自动补查。部署为 `dual_tools/general_qa` 和 `AGENT_PROVIDER=disabled`；dual_tools 是配置名称，不表示本期必须配置两个工具。

## 2. 已完成的实现

| 能力 | 交付内容 | 证据边界 |
| --- | --- | --- |
| 英文门户 | 麦克风/原始 PCM WAV 输入，连续收发、字幕、播放控制、知识答案与来源 | 浏览器测试与现场操作不等于所有声学环境通过 |
| 原生工具接入 | 注册内容核对、精确工具名/schema、最终输入关联、权限/版本复核 | Prompt 一致不保证模型每次正确选择工具 |
| CueKB 执行 | 服务端 KB/凭据，真实 query、无原生 HTTP 自动重试、完整来源过滤及 trace | 检索成功不等于材料充分回答问题 |
| 查询收敛 | 每输入两次实际查询、相同参数复用并终态、累计证据同时用于回填/校验/引用 | Black Pig 已有现场成功；不推定所有问题均服从终态 |
| 批次结清 | VoiceChat 声明解码批次，API 在预算内执行，超额成员结清，每批一份结果注入 | Golden Yolk 自动/Web 各有一次现场闭环证据；内容与时延未放行 |
| 业务提交 | Coordinator 唯一提交，隔离失效 epoch/revision/权限，检查实际答案与证据 | 播后有限检查不能撤回已播内容或代替人工核实 |
| 验证交付 | 输入/脚本内置镜像，docker exec 单入口、精简摘要和同通话时间线 | 合成服务和 CPU 测试不证明 GPU、真实内容或听音 |

## 3. 当前改进范围

本轮包括尚未部署的回答覆盖度与结果注入时延、Web 流式文字展示，并补充同一通话连续发送 WAV 与转后台不主动结束。稳定事实规则在会话提示中注册；工具结果保留逐项回答和停止搜索指引，去除通用来源标题，不裁切准入事实与条件。流式文字按 epoch/input/response 关联，历史与实时使用同一响应键；ACK 与正式回答分开，权限撤销继续隐藏内容。

文件在 EOF 后可继续 Choose WAV → Send recording，沿用会话和聊天历史；原始 PCM 分帧由 Worklet 时钟推进，不用窗口定时器。隐藏页面不停止 session，回前台尝试恢复音频；系统冻结、真实断流和时长限制仍生效。

后台持续播报按用户决定暂缓，作为非阻塞待优化项；本轮保留上述实现，在前台完成问答、连续文件输入及文字展示验收，不要求前后台无差异。

上一版尚未部署，合并更新 API/Web 镜像并新建通话；新增 Hello/TCP 句首缺失的定位入口与 VoiceChat audio_server.py 元数据诊断，不改模板、模型、RNNT 或参数，无数据库迁移。首 4 秒指纹只证明音频边界一致，转写哈希只证明文字交接一致，不能代替识别准确性和模型理解验收。现有 105 秒连接上限及额外 30 秒宽限保持，标为待优化，不纳入本轮编码。

## 4. 已知事实与未解决问题

- **已知事实：**Black Pig 单 case 自动验证曾达到 answered、10 条引用、两次查询、终态后零调用；最新 Web 已出现 Checking knowledge。不能继续概括为始终没有调用工具，也不能据此宣称所有产品回答正确。
- **已知事实：**Golden Yolk 第二段第 3 调用在第 2 终态结果提交前已收到。按出队时状态拒绝它有误；本次已编码修正，最新自动/Web 均已提交 answered 和 5 条引用；回答覆盖与注入时延仍需改进。
- **合理推断：**逐调用回填与后端单份待注入结果不匹配，存在覆盖风险；现场并未唯一证明结果被覆盖。本次以显式批次一次注入消除此风险。
- **已知事实：**两份最新关联日志将约 35.5 秒正式首包等待中的约 28.5 秒定位到两次逐 token 注入，CueKB 两次合计约 0.2 秒。缩短包装和重复指令是否实际降低等待，仍需下一版现场对照。
- **尚未放行：**逐项回答覆盖、Web 内容忠实性及重复回答、完整多轮/工具等待打断。Hello/TCP 句首缺失已进入定向定位，尚未确认根因或修复；不通过补文字、增加前置静音或修改识别阈值掩盖现象。
- **待优化，非阻塞：**后台持续播报尚未完成跨设备实机验收；浏览器/系统可能暂停音频或脚本并触发断流保护。后续单独评估播放中切后台、后台等待结果后开始播放及锁屏，不纳入本轮功能交付条件。

## 5. 验收与退出条件

本次 Golden Yolk 自动/Web 各一次，原 WAV 不修改，两个测试各用新连接；记录第二段输入、调用、真实查询次数、批次结果、非 ACK 文本/音频结束及引用。查询不超过 2、每批一次注入只是执行正确；必须完成有据回答或诚实部分回答，并人工核对来源和实际听音。

随后再推进同连接普通问答→知识查询→追问及麦克风打断；不能用分开新建连接的文件测试宣称多轮全部通过。两次无新增证据即停止同一修复思路，三种假设仍不解决时报告阻塞，不提高预算、降低内容要求或无休止重复测试。
