# 一期交付说明

更新：2026-10-23，开发主线 `main`，基线来自 `codex/q1003`。本文明确交付范围；实际架构见 [architecture.md](architecture.md)，待办与证据分别见 [任务板](TASK_BOARD.md) 和 [统一验证手册](validation.md)。代码完成、现场验证和产品放行是三个不同状态。

## 1. 需求与目的

建设仅支持英文（en-US）的全双工知识客服。用户通过 Web 麦克风或固定 WAV 发起语音问答，私有部署 NVIDIA VoiceChat 负责理解、原生工具选择、语音回答及连接内多轮上下文；外部 CueKB 提供企业知识。本项目负责门户、会话、授权、工具执行和有来源答案交付。

本期先打通一个完整、有据的知识问答，再验证连续多轮。查询得到部分信息时回答有据部分，明确本次材料无法确认哪些细节；不得把未检索到说成事实不存在。一般问候和通用知识允许直接回答，不能伪装为企业知识答案。

设计保持简单：一个 VoiceChat 会话、一条持续音频链路、一个原生 `search_knowledge_base(query)`、每输入默认两次实际查询。没有额外分类模型、独立 ASR/TTS、外置答案模型或转写触发的自动补查。部署为 `dual_tools/general_qa` 和 `AGENT_PROVIDER=disabled`；dual_tools 是配置名称，不表示本期必须配置两个工具。

## 2. 已完成的实现

| 能力 | 交付内容 | 证据边界 |
| --- | --- | --- |
| 英文门户 | 麦克风/原始 PCM WAV 输入，连续收发、字幕、播放控制、知识答案与来源 | 浏览器测试与现场操作不等于所有声学环境通过 |

## 3. 当前改进范围

本轮接入 CueKB V2（基线 dac382e），不再使用旧 M3 在线响应。Adapter/Citation 保留适用范围、必要上下文、原文位置及真实排序信息；原生模型包只投递精简的正文、可读归属和必要条件。完整组装不下时整组省略并记录原因，必要依赖 unresolved 不因主块完整而绕过。unknown/ambiguous 明确保留，不根据 query 补产品；文档标签不升级为局部事实归属。无 reranker 正常检索，本轮不引入 MMR 或新模型。

保留已有 PAD 完成后等待新输入、按输入两次查询、批次结清、精确来源去重和累计证据校验/引用；空的正常补充检索不抹掉已知事实，依赖失败不能冒充正常未命中。内容检查失败仍 failed，有权限的来源供复核，权限失效隐藏。流式文字按 epoch/input/response 关联，ACK 与正文分开。原有提示对覆盖的要求只是模型引导，不能当作语义正确性保证。

文件在 EOF 后可继续 Choose WAV → Send recording，沿用会话和聊天历史；原始 PCM 分帧由 Worklet 时钟推进，不用窗口定时器。隐藏页面不停止 session，回前台尝试恢复音频；系统冻结、真实断流和时长限制仍生效。

后台持续播报按用户决定暂缓，作为非阻塞待优化项；本轮保留上述实现，在前台完成问答、连续文件输入及文字展示验收，不要求前后台无差异。

更新 API/Web 镜像并新建通话；本轮不修改或要求重启已匹配的 VoiceChat。CueKB 管理员先准备其 0004 迁移、原文 evidence-v2 重处理、审核归属及发布、V2 索引/generation；不能只重建索引期待旧文档自动补归属。保留已部署的 RNNT 显示转写修正、正常分轮/打断门槛、权重及工具格式。本项目无新增数据库迁移，不加新模型/分类器/重试。现有 105 秒连接上限及额外 30 秒活动宽限保留，后台持续播报仍暂缓。自动验证在正式完成后观察 5 秒，并在 Golden Yolk 后自动发送同连接 Hello，不允许通过首个 done 就放行重复回答。

## 4. 已知事实与未解决问题

- **已知现场事实：**最近一次旧版 auto core 中，两产品均在两次查询内完成单次正式回答，5 秒无额外回答，Golden Yolk 后同连接 Hello 正常。Golden Yolk 首包/注入合计约 22.86/16.73 秒，Black Pig 约 36.24/29.96 秒；CueKB 两次查询合计均约 0.2 秒，等待主要在结果注入。
- **已知内容问题：**Golden Yolk 漏答运输、遗漏 15 天限定并无依据地区分名称；Black Pig 比例被说成小数、65 g 漏答、最佳食用与保质期混淆、三天条件缺乏已展示的鲜肉依据。Black Pig 的 VOICE_MISSING_CONDITION 只反映有限词法拒绝，Golden 的自动 passed 不能证明内容正确。
- **本轮实现、待真实验收：**V2 归属/完整依赖交接、按完整组预算、精简模型载荷、公开契约与有界诊断；旧数据重处理和真实 CueKB/GPU 尚未验收。已有流程控制保留，不用新模型或放宽门禁隐藏问题。
- **尚未放行：**产品属性归属、所问字段覆盖、英文数字/比例保真、真实注入提速、完整多轮与工具等待打断。CueKB 标记 complete 只证明已识别的必要组完整，不证明问题已全回答。
- **非阻塞待优化：**后台持续播报和连接寿命/轮换体验，按用户决定不纳入本轮修改。

## 5. 验收与退出条件

本次两个产品自动/Web 各一次，原 WAV 不修改；自动 Golden Yolk 随后在同连接发送 Hello，Black Pig 与 Web 产品测试各用独立连接；记录第二段输入、调用、真实查询次数、批次结果、非 ACK 文本/音频结束及引用。查询不超过 2、每批一次注入只是执行正确；必须完成有据回答或诚实部分回答，并人工核对来源和实际听音。

当前同连接 Hello 仅验证完成后能继续下一问，复杂指代及麦克风打断后续单独验收；不能用分开新建连接的文件测试宣称多轮全部通过。两次无新增证据即停止同一修复思路，三种假设仍不解决时报告阻塞，不提高预算、降低内容要求或无休止重复测试。
