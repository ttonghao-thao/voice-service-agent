# 一期交付说明

更新：2026-10-22，开发主线 `main`，基线来自 `codex/q1003`。本文明确交付范围；实际架构见 [architecture.md](architecture.md)，待办与证据分别见 [任务板](TASK_BOARD.md) 和 [统一验证手册](validation.md)。代码完成、现场验证和产品放行是三个不同状态。

## 1. 需求与目的

建设仅支持英文（en-US）的全双工知识客服。用户通过 Web 麦克风或固定 WAV 发起语音问答，私有部署 NVIDIA VoiceChat 负责理解、原生工具选择、语音回答及连接内多轮上下文；外部 CueKB 提供企业知识。本项目负责门户、会话、授权、工具执行和有来源答案交付。

本期先打通一个完整、有据的知识问答，再验证连续多轮。查询得到部分信息时回答有据部分，明确本次材料无法确认哪些细节；不得把未检索到说成事实不存在。一般问候和通用知识允许直接回答，不能伪装为企业知识答案。

设计保持简单：一个 VoiceChat 会话、一条持续音频链路、一个原生 `search_knowledge_base(query)`、每输入默认两次实际查询。没有额外分类模型、独立 ASR/TTS、外置答案模型或转写触发的自动补查。部署为 `dual_tools/general_qa` 和 `AGENT_PROVIDER=disabled`；dual_tools 是配置名称，不表示本期必须配置两个工具。

## 2. 已完成的实现

| 能力 | 交付内容 | 证据边界 |
| --- | --- | --- |
| 英文门户 | 麦克风/原始 PCM WAV 输入，连续收发、字幕、播放控制、知识答案与来源 | 浏览器测试与现场操作不等于所有声学环境通过 |

| 查询收敛 | 每输入两次实际查询、相同参数复用并终态、累计证据由本问题原生工具历史及新增完整来源共同提供，校验/引用保持累计 | Black Pig 已有现场成功；不推定所有问题均服从终态 |

## 3. 当前改进范围

本轮补齐 PAD 强制完成后的等待新输入边界，修正来源面板的失败阶段描述，并改进回答覆盖与结果注入。稳定事实规则在会话提示注册，复合 query 覆盖全部所问属性；缺失项合并说明、保持产品归属。每输入已成功交付的完全相同来源不重复注入，新增完整事实与条件照常发送，累计证据继续校验并落库。内容校验失败仍 failed；授权来源可供复核，权限失效隐藏。流式文字按 epoch/input/response 关联，历史与实时使用同一响应键；ACK 与正式回答分开，权限撤销继续隐藏内容。

文件在 EOF 后可继续 Choose WAV → Send recording，沿用会话和聊天历史；原始 PCM 分帧由 Worklet 时钟推进，不用窗口定时器。隐藏页面不停止 session，回前台尝试恢复音频；系统冻结、真实断流和时长限制仍生效。

后台持续播报按用户决定暂缓，作为非阻塞待优化项；本轮保留上述实现，在前台完成问答、连续文件输入及文字展示验收，不要求前后台无差异。

更新 API/Web 镜像并新建通话；VoiceChat 配套加载完整 model.py/data_types.py，重载整个容器。保留已部署的 RNNT 显示转写修正、正常分轮/打断门槛、权重及工具格式。没有数据库迁移，不加新模型/分类器/重试。现有 105 秒连接上限及额外 30 秒活动宽限保留，后台持续播报仍暂缓。自动验证在正式完成后观察 5 秒，并在 Golden Yolk 后自动发送同连接 Hello，不允许通过首个 done 就放行重复回答。

## 4. 已知事实与未解决问题

- **已知事实：**此前现场五次产品响应均由 PAD 保护强制 EOS，之后四次无新输入/工具结果而再次开口；检索约 0.2 秒，逐 token 注入占主要等待。Hello/TCP 句首识别按用户多次正常反馈收敛。
- **已实现、待现场验收：**强制完成后等待、首帧新语音/有效回填恢复、同输入精确来源去重、累计证据校验/引用、准确的失败标签、有界观察和首个正式响应计时。本地回归不证明 GPU 真实续答或时延达标。
- **已知事实：**此前 failed 被统一显示为 Search failed；播后检查失败也清空引用，造成检索与答案状态混淆。现在内容失败仍 failed 并明确 Answer not verified；权限有效时保留检索来源供复核。Reply complete 不代表所有字段都已查明。
- **仍未知：**最新 Black Pig 截图对应的具体 reason；不能未读取对应检查结果就认定为某项条件遗漏，也不能仅凭语音包含来源措辞断定事实正确。
- **尚未放行：**Golden Yolk 的运输/保质期/开封储存覆盖、产品属性归属、两产品的真实 GPU 首包/注入时延、完整多轮与工具等待打断。来源更新沿用本问题模型历史的真实效果须现场核对，不以字节减少代替时延或正确性证据。
- **非阻塞待优化：**后台持续播报和连接寿命/轮换体验，按用户决定不纳入本轮修改。

## 5. 验收与退出条件

本次两个产品自动/Web 各一次，原 WAV 不修改；自动 Golden Yolk 随后在同连接发送 Hello，Black Pig 与 Web 产品测试各用独立连接；记录第二段输入、调用、真实查询次数、批次结果、非 ACK 文本/音频结束及引用。查询不超过 2、每批一次注入只是执行正确；必须完成有据回答或诚实部分回答，并人工核对来源和实际听音。

当前同连接 Hello 仅验证完成后能继续下一问，复杂指代及麦克风打断后续单独验收；不能用分开新建连接的文件测试宣称多轮全部通过。两次无新增证据即停止同一修复思路，三种假设仍不解决时报告阻塞，不提高预算、降低内容要求或无休止重复测试。
