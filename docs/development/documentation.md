# 文档维护与按需读取

这是维护文档体系时的操作说明，常规编码不必读取。本次文档核对基线为 `f498fa4`，只修改 Markdown。

## 1. 信息归属

| 信息 | 唯一维护位置 | 其他文档怎样引用 |
| --- | --- | --- |
| 日常工作规则/读取策略 | AGENTS.md | 只保留跨任务不变量，具体设计转主题 |
| 路径、职责、任务触发与依赖 | docs/README.md | 导航不复制正文；新增/移动/职责变化才更新 |
| 跨模块边界/数据流 | architecture.md | 主题只描述本模块，跨边界给链接 |
| 决策原因、取舍、替代关系 | decisions/architecture-decisions.md | 不复制配置/接口表；保留历史依据 |
| 字段/枚举/路由 | contracts.py、工具 schema、routes.py 与生成契约 | 门户/CueKB/接入分别解释各自协议语义；代码冲突优先核代码 |
| 配置默认值与运行操作 | config.py、.env.example、deployment.md | 其他文档引用配置章节，不维护第二套参数表 |
| 实现、开发中、计划与已替代状态 | TASK_BOARD.md | 已实现与真实验收分开；正文不反复复制里程碑 |
| 最新实际验证 / 验收目标 | acceptance-report.md / development/validation.md | 测试数有日期/版本，目标矩阵不是 passed |
| 历史方案/流水 | archive/README.md 指向的日期快照 | 默认不加载，不能替代当前主题 |

相对路径从 docs 起算；代码和入口文件从仓库根起算。索引是查询表，不是必须依次读取的清单。

## 2. 修改与阅读规则

先 AGENTS → 任务明确时直接定位代码/主题，任务不明确时查索引。长文先标题/关键词，再截取目标章节；只有涉及调用方、共享状态、权限或数据契约才追加依赖。不要因节省上下文而省略必要事实；文档不足先读源码与相关测试，无法核实则标未确认。

| 修改类型 | 必须核对 | 文档更新范围 |
| --- | --- | --- |
| 局部内部修复，外部行为/约束不变 | 调用方及相关回归 | 通常无需改文档；不机械更新任务板或验收日期 |
| 字段/事件/API 行为变化 | 契约源、生成 schema、客户端及兼容性 | 对应门户/外部接口页；仅路径/职责变动才改索引 |
| 状态机、权限、预算或恢复语义变化 | 跨模块提交/输出与持久化 | 对应主题；任务状态改变再改任务板；新验证才记验收 |
| 配置/迁移/镜像操作变化 | Settings、模板、Compose、迁移及脚本 | 部署；别在所有 README 复制版本/默认值 |
| 架构决策变化 | 当前模块、ADR、实际依赖和必要历史依据 | 更新相关 ADR/主题；旧决策标已替代，不覆盖原原因 |
| 文档重组 | 目标/锚点、信息保留、读取路径 | 索引和受影响链接；纯 Markdown 无需重跑应用测试 |

扩展主题只有在独立职责或长文确实妨碍检索时才拆；不按空目录模板铺文件。变更后检查相对链接/章节、围栏和示例，`git diff --check`；契约/schema 仅在代码契约变化时导出，不为文档任务制造非 Markdown 差异。

历史归档保留源版本和日期，正文仅可为导航重定位链接；新的事实/结果另记日期。旧文档“本轮未实施”不作为当前开发状态。Markdown 链接是按需入口，避免递归读档案、生成 JSON、锁文件和测试产物。

### 3.1 盘点与最小方案

优化前 16 份 Markdown：AGENTS 4833 字节、导航 5822；问答设计 69836、验收 58452、门户 30461、架构 25547。主要问题是当前实现与计划/阶段流水混放、架构与接口/配置重复、AGENTS 与索引重复路由、旧基线和过期字段说明。

采用最小必要重组：保留既有主题路径；重写当前架构/知识执行/门户，验收当前结论与长流水分离。仅按独立职责抽出 CueKB 契约、故障排查和真实验收，补决策原因与本维护页；没有为目录齐全新建空模块文档。历史完整正文按日期归档。
