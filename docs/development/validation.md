# 一期验收要求

需求与边界见 [交付说明](../delivery.md)，已执行事实见 [验收记录](../acceptance-report.md)。本页是标准，不是通过声明。

## 1. 当前执行顺序

协同更新 API、Web 和 VoiceChat audio_server 后，先按 [批次验收](../native-tool-batch-validation.md) 各做一次 Golden Yolk 自动/Web 测试。只核对第二段知识闭环及批次处理，不同时改 WAV、提示词或预算。

闭环通过后验证 Black Pig 内容与重复响应，再执行同连接多轮和麦克风打断。模型未调用、查询失败、结果注入失败、答案未完成、内容错误分别记录，不把某层通过升级为全流程通过。

## 2. 放行标准

| 范围 | 要求 |
| --- | --- |
| 配置/版本 | 英文 en-US、dual_tools/general_qa、AGENT_PROVIDER=disabled；API/Web/VoiceChat 与 manifest 匹配 |
| 知识调用 | 产品请求触发正确工具，query 与用户目标一致，KB/凭据由服务端控制 |
| 有限查询 | 每 input 实际 HTTP 查询不超过预算，无自动重试；重复查询/预算终态按协议收敛 |
| 批次 | 明确批次成员与顺序，每批一次注入；超额排队成员结清，不伪报终态后新调用 |
| 自动回答完成 | 最新输入的非 ACK 文本、非零音频及结束事件齐全；业务 answered 且有引用 |
| 内容 | 已知事实、数值与条件有来源；无法确认部分明确说明；不编造，不将未命中等同不存在 |
| 普通问答 | 不依赖企业资料的问题可无工具回答；不显示伪来源 |
| 连续多轮 | 同连接继续追问，代词/对象正确，预算按新输入重置，无旧结果覆盖 |
| 全双工 | 麦克风持续收发、真实打断/恢复正确；等待工具时能力单独记录，不能由 ACK 推断 |
| 权限/恢复 | 越权和撤权拒绝，失效任务不提交，断线和轮换有明确状态，不自动重放未知交付 |
| 部署 | 迁移/健康/TLS/受控网络符合部署文档，密钥不进客户端或日志 |

部分答案可以通过，但必须准确回答有据部分并声明本次证据不足之处。收到音频、来源数量大于零、提交终态或诊断 passed 均不能独立证明内容达标。

## 3. 证据与停止条件

记录版本、样本、UTC 窗口、conversation/input/call/response/batch、检索 trace、结束状态和人工结论。只回传最少必要摘要/字段，原日志和授权录音留在受控位置，不提交仓库。

本地 CPU/协议夹具证明实现规则，真实服务日志证明该次链路观察，人工核对证明该次内容与听音；三者不能互相替代。未执行、失败、不适用分别记录。

同一思路两次无新证据即停止；三种假设仍不解决则报告环境/设计/技术路径阻塞。非阻塞项记录后退出，不提高查询上限或降低验收标准来获得绿色输出。
